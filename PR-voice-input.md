Title: Voice input on Translate: /transcribe endpoint and the recording row

## Що це

Український голосовий ввід як **спосіб набору** на Translate, не «голосові повідомлення». Клієнт пише кліп через `MediaRecorder`, відправляє його на власний ендпоінт `POST /api/v1/transcribe`, розпізнаний текст дописується в кінець чернетки й далі йде звичайним шляхом preview/save. Контракт `POST /translate/preview` не змінився, окремого типу записів у History немає.

## Backend

- `POST /api/v1/transcribe` (JWT): тіло `{ audio: base64, mimeType }`, відповідь `{ text, model }`. OpenAI-сумісний провайдер за `STT_BASE_URL`/`STT_MODEL` (Groq `whisper-large-v3-turbo` за замовчуванням).
- Власний `KeyPool` (`STT_API_KEY`, id `stt`) з власними кулдаунами — вичерпана квота розпізнавання не має паркувати ключ, потрібний перекладу.
- Власний ліміт 6/хв на користувача (`ratelimit:stt`), allowlist контейнерів і стеля розміру перевіряються **до** буферизації тіла.
- Порожній `STT_API_KEY` = функції не існує: `voiceInputAvailable: false` у `GET /user/me` і кнопки немає взагалі, замість мікрофона, що завжди відповідає `503`.
- **Аудіо не зберігається ніде** — ні Postgres, ні Redis, ні тимчасовий файл, ні лог; так само транскрипт. Це головне твердження `test/integration/transcribe.integration.test.ts`, а не обіцянка в документації.
- Рефакторинг окремим комітом (`b1e3400`): класифікація вичерпаних ключів витягнута з `base.adapter.ts` у `src/services/ai/key-exhaustion.ts`, щоб STT і переклад читали її з одного місця. Це єдина частина PR, що торкається наявного шляху перекладу — дивитись разом із `test/unit/key-exhaustion.test.ts`.

## Frontend

- Три шари: `useAudioRecorder` (нічого не знає про API) → `useVoiceInput` (запит + свій текст на кожен код помилки) → `TranslatePage` (не тримає стану запису).
- Мікрофон у рядку дій редактора, на місці колишньої «Вставити». У спокої — коло 44×44, залите синім, як «Поділитись».
- Запис: та сама кнопка розтягується в рядок запису — блимаюча точка, відлік **угору** в секундах (`03`; стеля 30 с, тому хвилин не буває), шкала гучності на 14 смужок і лінійка витраченого ліміту вздовж низу. Місце дає «Випадкова фраза», що згортається до кубиків; правий чип стає «Скасувати запис».
- Скасування нічого не надсилає й не показує помилки. Раніше не надіслати сказане можна було лише дочекавшись тридцятої секунди.
- Шкала читає реальний рівень через Web Audio, але поза рендером React (`sampleLevel()` + CSS-змінні, ~15 fps) і best-effort у трьох напрямках: немає `AudioContext`, немає `requestAnimationFrame`, `prefers-reduced-motion`. `AudioContext` закривається разом із мікрофоном, інакше системний індикатор запису лишається світитися.

## Конфігурація

Дванадцять змінних `STT_*` (див. `.env.example`). Схема Zod у `src/config/index.ts`, `.env.example`, розділ env у README і `docs/configuration.md` збігаються один в один; жодного значення ключа в репозиторії немає.

## Перевірка

- `npx tsc -b` у `frontend/` — чисто.
- Юніт- і інтеграційні тести бекенду, `npm run lint` і `npm run test -- --run` у `frontend/` — запускаються на машині власника (у контейнері розробки vitest і oxlint не працюють, інтеграційні тести потребують Docker Desktop).
- Мікрофон у Telegram на Android та iOS перевіряється вручну: дозвіл, шлях `AudioContext` для шкали і вигляд розтягнутої пігулки на 360px.
